Проверка: 2026-11-27, по исходным файлам GitHub. **Это ревью исходников и CI, не pentest и не юридическое заключение.**

## SEO Engine — что есть / чего нет
**Прочитано:** `seo/ENGINE_README.md`, `seo/engine.py` (ключевые методы), `seo/test_engine.py` ветки PR #1.
- Есть каталог черновых посадочных страниц, строгие проверки путей и уникальности, генерация noindex-предпросмотра, отбор публикации по признаку `approved`, тесты.
- **Важное ограничение:** значение `approved_by` в JSON само по себе не доказывает редакционное согласование. Для реального релиза нужен процесс подписанного утверждения/рецензии и источников, не только флаг в JSON.
- Не проверены в браузере качество контента всех страниц, картинки/лицензии, реальные Core Web Vitals, позиции и поисковая индексация; для них требуются внешние измерения и разрешённый продакшен.
- Гейт: оригинальные услуги/контент, право на фото, проверенные контакты/оферта/правовые страницы, канонический домен/DNS+HTTPS, ручная редактура, QA и только после отдельного согласования robots/sitemap/IndexNow.
- Важно: preview остаётся noindex; утверждение лендингов в отдельной сборке не даёт права автоматически включать индексацию.

## Secure Intake — что есть / чего нет
**Прочитано:** `intake/README.md`, `intake/server.py` и `intake/test_server.py` ветки PR #2.
- Есть изолированный WSGI-прототип на Python: по умолчанию обработчик заявок возвращает 503; при включённом тестовом режиме валидирует форму, версию согласия, структуру, телефон/ИНН, Origin, размер тела; использует UUID для идемпотентности и SQLite для локального теста; CI покрывает синтетику.
- **Не готов для реальных ПД:** SQLite содержит открытые поля, нет операционного кабинета/аутентификации/MFA, шифрования с управлением ключами, очереди задач, удаления и хранения по утверждённым срокам, проверенного резервного восстановления, production reverse proxy с per-client rate limit, антибота, мониторинга и релизных правовых материалов. Глобальное ограничение 30/мин — не полноценный per-client rate limit.
- Параметр `LK_ENABLE_INTAKE=approved` — технический переключатель, а не подтверждение юридической готовности. Включение запрещено без согласования оператора, согласия, приватного хостинга РФ и полномочий.
- Гейт: до любого реального POST подготовить производственную БД + операторский защищённый UI/очередь + политику удаления + отдельную защиту от атак/спама + эксплуатационные проверки + утверждённые документы и правовые основания. Клиентский интерфейс нельзя напрямую соединять с локальным прототипом.

## Broker Core — реализованная синтетика
- `broker/offer_comparison.py` — сравнение 2–20 проверенных КП с оригинальным идентификатором, явными выплатами, одинаковой базой, валидностью дат; никогда не угадывает отсутствующие суммы.
- `broker/case_workflow.py` — рабочая модель стадий, назначений и конкуренции обновлений в памяти, не сервер и не CRM с базой данных.
- `broker/access_policy.py` — чистый вычислитель RBAC/tenant/case, не реальная идентификация.
- `broker/demo.py` — сценарий на условных данных; `broker/test_*.py` — машинные тесты в GitHub Actions.

## Очерёдность релиза без ненужных рисков
1. Зафиксировать бизнес-процесс брокера: кто создаёт заявку, кто распределяет, кто утверждает сравнение, кто видит документы.
2. Построить защищённый backend в РФ с MFA/сессиями, PostgreSQL, объектным хранилищем, audit trail, режимами тест/prod, миграциями и per-object правами; проверить отказоустойчивость и резервное восстановление.
3. Перенести P0 Case/Offer Desk в серверный слой; 2–20 оригинальных КП, статусы и проверяемые сравнения, реальные источники только с договорными правами.
4. Подготовить законный Secure Intake, consent lifecycle, anti-bot, CSRF/Origin/CORS, operator queue. **Только после разрешения** включать реальные заявки.
5. Документы/OCR/Legal/Verify и интеграции через очередь + ручной контроль, потом Market/Radar/Subsidy/Vision.
6. Оформить публичный SEO релиз и индексацию отдельно; до этого preview остаётся скрыт от индексации.

## Принцип готовности
Наличие файла, успешного unit-теста или GitHub Action **не равно** готовому клиентскому сервису, безопасной работе с ПД, юридической чистоте, подтверждённому КП или запущенной индексации.
