# Compass Broker — рабочий локальный режим P0.2

**Реально работающий локальный финансовый процесс**, не публичный сайт и не production-CRM.
Новые сделки, условия КП, этапы и журнал сохраняются **в SQLite на том ПК**, где запущен сервер. Данные не отправляются на GitHub, в облако или кому-либо по сети. Сервер слушает ТОЛЬКО `127.0.0.1`. Не открывать порт в LAN/интернете, не использовать VPN-туннели/проброс/прокси.

## Запуск на собственном ПК (Windows 10/11, Python 3.12+)

Нужен только установленный Python и локальная копия репозитория. Никаких `pip install` не требуется.
Из каталога репозитория:

```powershell
python -m unittest discover -s broker -p "test_*.py" -v
python broker/local_server.py
```

Программа попросит задать пароль **от 14 символов** в консоли. Пароль не сохраняется в файлы, не передавайте его в ChatGPT. Откройте **на том же ПК**:

`http://127.0.0.1:8765/`

Войдите с заданным паролем → раздел **«Рабочие сделки»** → **«Создать сделку»** → «Начать сбор КП» → заполнить подтверждённые поля КП (минимум 2) → «Сравнить КП» → «Журнал действий». Доступно завершение сделки (для единственного локального оператора). Кнопка **«Выйти»** закрывает сессию. Остановка: `Ctrl+C` в консоли сервера. Никаких фоновых автозапусков.

По умолчанию база: `%USERPROFILE%\CompassBrokerLocal\broker.sqlite3`. Для синтетической QA-среды можно задать абсолютный путь через `LK_LOCAL_DB` (например, в Temp). Не направлять путь в публичные каталоги.

## Реально реализовано

- Пароль, сессия в памяти, `HttpOnly` + `SameSite=Strict` cookie, CSRF-токен на запись; парольный подбор ограничен; одинаковый Origin и Host; запрет CORS; лимит тела; запрет произвольных HTTP-путей.
- Создание финансовой сделки (рубли/сумма/аванс/срок/база НДС), выдача по назначенным делам, версии изменений, этапы.
- Добавление КП с источником как непрозрачным ID, датой действия, ценой, выкупом, разовыми и ежемесячными расходами, страховкой; нельзя подменять отсутствующий платёж нулём автоматически, нужен явный ввод.
- Сравнение по существующему движку `offer_comparison.py`; несопоставимые или непроверенные КП остаются без рейтинга.
- Хранение финансовых кейсов и журнала в локальной SQLite, восстановление после перезапуска.
- Плавное переключение светлой нейтральной и тёмной приглушённой темы; отдельные удобные рабочие формы.
- Автоматические регрессионные тесты API и безопасности запускаются в GitHub Actions на Windows + Linux. Графический QA на реальном телефоне проводится отдельно.

## Принципиальные ограничения

1. **НЕ вводить реальные ФИО, телефоны, e-mail, ИНН, адреса, договоры, документы или клиентские реквизиты.** Локальный API отвергает неизвестные поля. Поле названия лизингодателя — только организация, без информации о клиентах. База не шифруется, аудит не является неизменяемым; нет production MFA.
2. **GitHub Pages — открытый сайт даже без домена.** Публичная страница `broker-preview.html` содержит лишь заранее вымышленные примеры. Скрипт `broker-local-ui.js` проверяет `http://127.0.0.1` и на GitHub Pages НЕ запускает API.
3. Локальный вход и сессии предназначены для **одного оператора на одном ПК**, не для команды, клиентов или удалённого доступа. Нет резервных копий, гарантий восстановления, внешних интеграций, загрузки документов и полноценной идентификации.
4. **НЕ включать публичные формы с реальной отправкой**, пока нет правового основания, безопасного размещения в РФ, подтверждённого оператора данных, HTTPS, production-аутентификации и независимого тестирования.
5. Статические скрипты, включая HTML прототипа, видны любому посетителю GitHub Pages. Безопасность клиентских данных не должна опираться на скрытые кнопки или `noindex`.
